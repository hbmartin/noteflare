# Upstream change assessment for NoteFlare

Assessment date: 20 October 2026. The target is a small team's daily shared wiki, with reliability and everyday usability followed by selected new capabilities. The agreed scope retains space permissions, adds immediate access revocation, extends tables with relations and rollups, and focuses integration development on Slack. Editing requires a connection; cached documents remain readable. Public sharing stays minimal. Conventional search and explicit-source AI writing remain in scope; automatic retrieval is deferred.

Use the [small team improvement roadmap](../roadmap/12-small-team-wiki-improvements.md) for implementation sequencing. **Adapt** means adopt the behavior through NoteFlare's architecture. **Verify** means reproduce the scenario before deciding whether a fix is needed. **Finish** means the capability already has an implementation. **Defer** means retain the idea without including its implementation in this program. **Different stack** means the referenced patch does not apply directly.

Implementation scope override: the user excluded new portability/import/export work, backups, page ownership/verification/freshness, and audit history after this assessment. Retained discussions of those upstream changes are research dispositions, not implementation authorization. Comments, reactions, settings, and trash remain in scope.

## Current implementation changes the starting point

- [Editor options](../../src/client/EditorPage.tsx) call [the multipart uploader](../../src/client/uploads.ts), which supports progress callbacks. The editor currently supplies no callback and discards BlockNote's block-ID argument. The installed BlockNote insertion path already places file blocks around existing blocks; placement needs verification before replacement.
- [Presentation](../../src/client/Presentation.tsx) already provides fullscreen, keyboard navigation, measured pagination, focus handling, and slide announcements. This is a polish increment.
- [TableAuthority](../../src/worker/table-authority.ts) and [the table protocol](../../src/shared/table-protocol.ts) already implement canonical commands, receipts, formulas, saved views, conversions, and projections. Relations and rollups are absent. Existing table cutover still needs the release work described in [the table acceptance record](../implementation/table-authority-release.md).
- [Document grants](../../src/worker/index.ts) are capped at five minutes. [Document rooms](../../src/worker/document.ts) enforce the captured grant's role and expiry. Table authorization rechecks membership for canonical requests. The revocation design must cover every room and grant type rather than assume identical behavior.
- [Sign-out](../../src/client/App.tsx) already reviews pending document changes, purges local account data, clears live recovery copies, and informs other tabs. Docmost's cache deletion behavior is substantially covered; the remaining work is verification and consistent revocation handling.
- [Search](../../src/worker/search.ts) already uses FTS5, weighted fields, filters, and title suggestions. Its query parser splits dot-separated text into quoted prefix terms; the underlying Unicode tokenizer differs from PostgreSQL. Headings currently share the body field.
- [Public preview fetching](../../src/worker/link-previews.ts) already caches successful and failed fetches, bounds requests, and uses the configured strictly-public fetch policy. [Bookmark components](../../src/client/editor-blocks.tsx) still perform their own client requests. [Internal preview cards](../../src/client/card-preview-pool.ts) and [diagram embeds](../../src/client/diagram-embed-pool.ts) already share subscriptions.
- [Public shares](../../src/worker/shares.ts) already support subpages, navigation, a heading outline, and optional indexing. The member OAuth endpoint advertises public clients with PKCE; Outline's confidential-client secret patch is not a matching implementation.
- The [roadmap index](../roadmap/README.md), [ideas backlog](../IDEAS.md), and older parity report have dated status statements. The implementation records and current source supersede those statements for planning purposes.

The [styled-components migration 14047](https://github.com/outline/outline/pull/14047), [Koa router migration 14042](https://github.com/outline/outline/pull/14042), [Koa middleware updates 14046](https://github.com/outline/outline/pull/14046), [Redis adapter and crypto-js replacements 14045](https://github.com/outline/outline/pull/14045), and the slug, dropzone, Radix, and Sentry upgrades are not a package checklist for NoteFlare. Dependency changes require compatibility with the existing local patches and an application-level regression case where relevant.

[Redis process-exit handling 14114](https://github.com/outline/outline/pull/14114) does not apply to a Worker. Adapt its reliability intent to bounded retries, health reporting, durable alarms, queue recovery, and a clear unavailable state. Prefer bounded error fingerprints in the existing telemetry system over copying Sentry-specific configuration. Cleanup passes [14092](https://github.com/outline/outline/pull/14092), [14124](https://github.com/outline/outline/pull/14124), and [14133](https://github.com/outline/outline/pull/14133), verification skills, and AGENTS changes are process references; update NoteFlare's own contributor checks around demonstrated failure modes rather than copy another project's instructions. ## Additional improvements from the parent repositories

The supporting sync repositories are infrastructure references rather than editor replacements. Keep the current Yjs/React Flow/PartyServer architecture. Extend acceptance to hibernation wake, presence cleanup, duplicate close/error delivery, cold-start sync, cross-tab startup, idle connection cost, and a realistic concurrency load. The tldraw example's ping auto-response is protocol-specific; verify the current provider's keepalive behavior before changing it.

For a daily team wiki, the broader repository comparison also supports complete workspace export and recoverable backups, lightweight ownership and freshness, collaboration drafts and reactions, consistent page navigation, and usable settings/recovery screens. Each belongs in the roadmap with a bounded user contract, authority model, failure behavior, and release evidence. Provider sprawl, multi-workspace tenancy, groups/guests, a replacement canvas stack, and enterprise SSO are outside the agreed core scope.
